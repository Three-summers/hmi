# 格科光阻稀释机台自动化改造项目背景与程序需求

本文整理格科光阻稀释机台自动化改造的现场背景、程序需求、外部系统交互、日志报表和待确认事项，作为后续 HMI 界面、工艺配方、设备控制、PRMS 通信和追溯报表设计的输入资料。

资料来源：

1. 前期手写需求说明。
2. `Dilution_程序需求.xlsx`：
   - `程序设置`：上料、粘度测试、出料、机台 Log、报表生成需求。
   - `报表样式参考`：报表字段与一批次多条码/多瓶次记录样式。
   - `Sheet3`：当前为空。

## 1. 项目目标

现有机台用于将不同光阻原液与稀释剂按指定关系混合。改造目标是把原本依赖人工判断和手工记录的稀释过程，升级为可在 HMI 上引导操作、自动计量、自动测试、自动打印、自动记录并与 PRMS/报表系统交互的流程。

改造后的系统至少需要覆盖：

1. 光阻原液扫码上料与条码校验。
2. 根据原液条码向 PRMS 查询原液、机台、稀释液光阻之间的 mapping 关系。
3. 根据光阻类型和稀释浓度锁定或选择 recipe。
4. 根据 recipe 自动抽取对应质量的光阻原液和稀释剂。
5. 按 recipe 执行搅拌、静置和粘度测试。
6. 根据最终稀释瓶数向 PRMS 创建或获取稀释液光阻 barcode，并触发打印。
7. 记录完整机台 Log，汇总生成报表并发送给报表系统。

## 2. 现场设备与外部系统

### 2.1 已知设备

| 设备 | 用途 |
| --- | --- |
| 扫码枪 | 扫描光阻原液 barcode，用于识别原液并触发 PRMS mapping 查询。 |
| 打印机 | 自动打印稀释液光阻 barcode 标签，标签粘贴由人工完成。 |
| 流量计 | 测量光阻原液和稀释剂加入体积，并作为质量计算或核算依据。 |
| 搅拌机 | 对混合后的液体执行搅拌。 |
| 电子阀门 | 控制原液、稀释剂或出料通路的开闭。 |
| 气泡计 | 用于检测管路内是否存在气泡，具体联锁策略待确认。 |
| 超声波粘度计 | 测量混合液体静置后的粘度值。 |

### 2.2 外部系统

| 系统 | 交互内容 |
| --- | --- |
| PRMS | 接收扫码查询，返回光阻与稀释液浓度配比 mapping；接收稀释瓶数信息；创建/返回稀释液光阻 barcode；接收粘度值；根据 limit setting 判断光阻是否 hold。 |
| Resist Portal | 展示 PRMS 生成的 Dilution Barcode。 |
| 厂务供液系统 | 接收机台供液/停止信号，控制 PGMEA 供液系统。 |
| 报表系统 | 接收机台汇总后的稀释报表数据。 |

## 3. 核心业务流程

```text
扫码原液 barcode
  -> 向 PRMS 查询原液/机台/稀释液 mapping
  -> 校验原液是否允许上机
  -> 锁定或人工选择稀释浓度
  -> 锁定 recipe
  -> 自动抽取光阻原液
  -> 按实际原液量计算并抽取稀释剂
  -> 搅拌
  -> 静置
  -> 粘度测试 2 次
  -> 计算粘度平均值并上传 PRMS
  -> 计算稀释液总量和瓶数
  -> 向 PRMS 发送瓶数信息
  -> PRMS 创建/返回 Dilution Barcode
  -> 自动打印标签
  -> 定量出料并逐瓶记录质量
  -> 生成 Log 和报表
```

说明：上面的顺序按 Excel 表格语义整理。实际实现时，条码申请/打印与出料动作的具体先后关系仍需结合 PRMS 接口和现场操作确认。

## 4. 配方与 Mapping

### 4.1 PRMS Mapping

扫码后，机台需要向 PRMS 询问并定位以下关系：

1. 光阻原液信息。
2. 当前机台是否允许处理该原液。
3. 原液与稀释液光阻之间的 mapping。
4. 可选稀释浓度和对应配比关系。

### 4.2 Recipe 选择规则

1. 单一稀释浓度的光阻：机台自动锁定稀释浓度和 recipe。
2. 多种稀释浓度的光阻：HMI 由人工选择稀释浓度后，机台自动识别并锁定 recipe。
3. recipe 锁定后，机台根据 recipe 抽取对应质量的光阻原液和稀释剂。

### 4.3 Recipe 基础字段

Recipe 建立在机台端，至少应关联以下关键字段：

| 字段 | 说明 |
| --- | --- |
| 光阻原液名称 | 用于和扫码识别出的原液匹配。 |
| 稀释浓度 | 用于区分同一原液的不同稀释方案。 |
| 原液/稀释剂配比 | 用于计算稀释剂需求质量，具体公式待确认。 |
| 搅拌时间 | 搅拌机运行时长。 |
| 静置时间 | 搅拌完成后等待粘度测试的时间。 |
| 粘度范围 | 用于本地显示或校验；PRMS 也会根据 limit setting 判断是否 hold。 |

### 4.4 上机校验规则

机台端至少需要校验两类规则：

1. 非机台设定的光阻：扫码后机台 Alarm，提示不能上机。
2. 同一批次稀释的多瓶原液：resist barcode 必须属于同一类光阻，否则机台 Alarm，提示不能上机。

相同 barcode 不应被简单地按“重复扫码”拦截，因为非整瓶上料后可能存在二次稀释场景。

## 5. 上料需求

### 5.1 自动上料总要求

上料阶段目标是自动上料、自动计量，并把实际抽取质量写入 Log。HMI 上点击光阻上料后，应展示至少两类输入方式：

1. `光阻质量`
2. `光阻瓶数`

系统根据操作员选择的模式执行整瓶或非整瓶上料。

### 5.2 光阻整瓶上料

整瓶上料流程：

1. 操作员在 HMI 点击光阻上料。
2. HMI 显示 `光阻质量`、`光阻瓶数`。
3. 操作员选择 `光阻瓶数` 并输入瓶数。
4. 机台整瓶抽取光阻液体，直到所需瓶数抽取完成。
5. 流量计根据已抽取瓶数对应的光阻质量，计算稀释剂需求质量。
6. 机台抽取稀释剂，直到所需稀释剂质量抽取完成。

整瓶上料的计量规则：

1. 光阻原液质量计算以流量计检测到的液体体积为依据。
2. `光阻液质量与体积是否 1:1` 需要 PE 确认。
3. 多瓶次按光阻质量计量时，输入的光阻质量仅作为预设 Max 值。
4. 原液质量以实际抽取质量为准，并据此计算稀释剂需求质量。
5. 抽取完成后，机台提示实际质量，Log 记录实际质量。

### 5.3 光阻非整瓶上料

非整瓶上料流程：

1. 操作员在 HMI 点击光阻上料。
2. HMI 显示 `光阻质量`、`光阻瓶数`。
3. 操作员选择 `光阻质量` 并输入目标质量。
4. 机台抽取输入质量的光阻原液，允许出现零点几瓶或几点几瓶。
5. 流量计以输入或实际抽取的光阻质量为依据，计算稀释剂需求质量。
6. 机台抽取稀释剂，直到所需稀释剂质量抽取完成。

剩余光阻原液需要允许后续继续使用。机台服务器和 PRMS 均应允许同一原液 barcode 下次扫码识别及二次稀释，不做“单次扫码只能使用一次”的硬卡控。

### 5.4 稀释剂上料

稀释剂和清洗剂为 PGMEA，由厂务 center supply 供应。稀释机台负责控制供液和停止信号：

1. 机台发送供液信号给厂务供液端。
2. 厂务根据机台信号开启 PGMEA 供液系统。
3. 机台发送停止信号给厂务供液端。
4. 厂务根据机台信号停止 PGMEA 供液系统。
5. EMO 需要与厂务供液系统联动。

PGMEA 供液信号形式、通讯协议、EMO 联动策略和异常恢复方式待确认。

## 6. 计量与计算规则

1. 流量计以体积作为直接测量基础。
2. 稀释程序以“质量”为主要计算与记录口径。
3. 若光阻或稀释剂密度不为 `1`，不能默认体积等于质量，需要引入密度换算。
4. 整瓶上料时，实际抽取质量优先于输入预设值。
5. 非整瓶上料时，需要确认稀释剂计算依据是输入目标质量，还是流量计换算后的实际抽取质量。
6. 最终 Log 应记录实际原液质量、实际稀释剂质量、稀释液总质量和逐瓶出料质量。

需要进一步确认：

1. 每种光阻和 PGMEA 的密度来源。
2. 密度是固定在 recipe/物料表中，还是由 PRMS 返回。
3. 原液、稀释剂、出料的允许计量误差。
4. 超差后的处理方式：报警、暂停、人工确认、自动修正或报废。

## 7. 粘度测试需求

### 7.1 自动测试

1. 机台根据 recipe 静置时间进入静置阶段。
2. 静置完成后自动启动粘度测试。
3. 粘度测试重复进行 2 次。
4. 2 次原始数据均计入 Log。

### 7.2 数据录入与判定

1. 2 次粘度数据的平均值作为最终粘度结果。
2. 机台将最终粘度结果发送给 PRMS。
3. PRMS 接收机台上传的粘度值。
4. PRMS 根据 limit setting 判断该光阻是否 hold。

需要进一步确认：机台本地是否只展示粘度范围和 PRMS 判定结果，还是也需要在本地直接做合格/不合格拦截。

## 8. 出料、Barcode 与标签打印

### 8.1 出料与稀释瓶次信息创建

1. 流量计记录光阻质量和稀释剂质量。
2. 机台自动计算稀释液光阻总质量和稀释瓶数。
3. 机台根据设置定量出料。
4. 当批次最后一瓶允许接收不满瓶光阻，不应作为异常报错。
5. 每一瓶出料光阻质量都需要记录在 Log。
6. 机台将稀释瓶数信息发送给 PRMS。

### 8.2 PRMS 创建 Dilution Barcode

1. PRMS 接收机台端稀释光阻瓶数信息。
2. PRMS 根据原液光阻 barcode 信息及系统 mapping，自动创建稀释液光阻 barcode。
3. Dilution Barcode 在 PRMS 生成，并显示在 Resist Portal。
4. 无论粘度值是否符合 limit setting，都不影响 Dilution Barcode 生成。

### 8.3 标签打印

1. 机台同步触发标签打印需求。
2. Dilution Barcode 自动打印。
3. PRMS 返回当批次稀释的稀释液光阻 barcode 给机台。
4. 标签打印、张贴遵循递增顺序进行。
5. 标签顺序需要匹配当批次每一瓶的出料光阻质量信息。

需要进一步确认：打印失败、标签重打、标签顺序错位时，机台与 PRMS 如何保持一致。

## 9. 机台 Log、报表与追溯

### 9.1 Log 记录与留存

机台需要进行全信息记录和留存。Excel 表格中该项写作 `机台logo`，按上下文理解为机台 Log。

Log 至少需要记录：

| 字段 | 说明 |
| --- | --- |
| 人员信息 | 作业员、核对员。 |
| 机台信息 | 机台编号，例如报表样式中的 `MCP-03`。 |
| 材料信息 | 原液名称、原液 barcode、稀释液光阻名称。 |
| Recipe | 使用的 recipe、稀释浓度、关键参数。 |
| 操作时间 | 稀释开始时间、稀释结束时间。 |
| 步骤时间 | 上料、搅拌、静置、粘度测试、出料等关键步骤时间。 |
| 搅拌信息 | 搅拌开始时间、搅拌结束时间。 |
| 测试信息 | 2 次粘度原始值、平均粘度值、PRMS 判定结果。 |
| 稀释液光阻信息 | 稀释瓶数、每瓶 Dilution Barcode、每瓶出料质量。 |

Log 留存时长暂定 1 年。

### 9.2 异常补账

如果机台或系统服务器 issue 造成信息重复发送、漏发送，并引发稀释液光阻接收问题，Excel 表格中提到可以通过 `ter barcode` 或 `Manual create` 补账。

这里有两个未确认点：

1. `ter barcode` 的准确含义需要 PRMS/FA 确认。
2. 因补账造成的 Log、PRMS 或报表异常，处理方案需要机台厂商和 FA 后续讨论。

### 9.3 报表生成

机台需要将稀释过程信息摘录、汇总、集成后发送给报表系统。

报表字段参考 `报表样式参考` sheet：

| 字段 | 说明 |
| --- | --- |
| 稀释日期 | 批次稀释日期。 |
| 原液名称 | 原液光阻名称，例如 `TMR-IK02 PM 5.4cP`。 |
| 原液 Barcode | 原液光阻 barcode；同一批次可有多条。 |
| 原液光阻质量 | 本批次原液实际质量。 |
| 原液瓶数 | 本批次原液瓶数。 |
| 机台 | 机台编号。 |
| 作业员 | 执行人员。 |
| 核对员 | 复核人员，可多人。 |
| 搅拌开始时间 | 搅拌开始时间。 |
| 搅拌结束时间 | 搅拌结束时间。 |
| 粘度测试时间 | 粘度测试时间或测试耗时，字段语义待确认。 |
| 粘度 | 最终粘度值，按当前需求为 2 次测试平均值。 |
| 稀释光阻名称 | 稀释后的光阻名称，例如 `IK02-70%`。 |
| 稀释光阻瓶数 | 最终稀释瓶数。 |
| 稀释光阻 Barcode | 每瓶 Dilution Barcode；同一批次可有多条。 |
| 稀释光阻质量 | 每瓶出料质量。 |
| Comment | 备注，例如 `PGMEA 作为稀释剂稀释`。 |

报表样式允许一个批次跨多行展示：批次级字段可合并，原液 barcode 和稀释光阻 barcode/质量按行展开。

## 10. 异常与人工介入

后续设计需要明确以下异常处理规则：

1. 条码无法识别。
2. 条码物料与机台设定不匹配。
3. 同一批次多瓶原液 barcode 不属于同一类光阻。
4. 扫码瓶数与计划瓶数不一致。
5. 相同 barcode 二次使用与非整瓶上料之间的判断规则。
6. PRMS mapping 查询失败或返回多解。
7. recipe 无法锁定或人工未选择浓度。
8. 流量计数据缺失、计量超差、电子阀门动作失败。
9. PGMEA 厂务供液失败或 EMO 触发。
10. 气泡计检测异常。
11. 搅拌机未启动、提前停止或运行超时。
12. 粘度计通信失败、测量超时、两次数据差异过大或结果超出范围。
13. PRMS 粘度上传失败、瓶数发送失败、Dilution Barcode 创建失败。
14. 打印失败、标签重打、标签顺序与出料顺序不一致。
15. 报表发送失败、重复发送、漏发送或补账后报表不一致。

每类异常都需要明确：是否暂停流程、是否允许人工确认继续、是否需要核对员确认、是否写入 Log、是否上报 PRMS、是否允许补账。

## 11. 开发落地关注点

### 11.1 HMI 页面与状态

建议后续 HMI 至少覆盖以下状态和页面能力：

1. 批次初始化：选择机台、登记作业员/核对员、输入计划瓶数或目标质量。
2. 扫码上料：显示扫码列表、条码校验状态、PRMS mapping 结果、原液类别一致性。
3. recipe 锁定：单浓度自动锁定，多浓度人工选择。
4. 上料计量：整瓶/非整瓶模式、实际抽取质量、稀释剂需求质量、计量偏差提示。
5. PGMEA 供液：供液/停止状态、EMO 状态、厂务供液异常。
6. 搅拌静置：搅拌开始/结束、静置倒计时。
7. 粘度测试：2 次原始值、平均值、上传 PRMS 状态、PRMS hold 结果。
8. 出料打印：稀释瓶数、每瓶目标容量、每瓶实际质量、Dilution Barcode、打印状态、人工确认。
9. Log/报表：批次详情、导出/发送状态、异常补账记录。

### 11.2 关键数据对象

建议后续实现时显式建模以下对象：

1. `Batch`：一次稀释批次。
2. `RawResistScan`：原液扫码记录。
3. `PrmsMapping`：PRMS 返回的原液/浓度/稀释液 mapping。
4. `DilutionRecipe`：机台端 recipe。
5. `MeteringRecord`：原液、稀释剂、出料计量记录。
6. `ViscosityTest`：2 次测试值、平均值、PRMS 判定。
7. `OutputBottle`：每瓶出料质量、Dilution Barcode、标签打印状态。
8. `PrmsSyncRecord`：PRMS 发送/接收、重试、补账状态。
9. `DilutionReport`：发送给报表系统的汇总数据。

### 11.3 外部接口

至少需要定义以下接口契约：

1. 扫码后向 PRMS 查询 mapping。
2. 向 PRMS 发送粘度结果。
3. 向 PRMS 发送稀释瓶数信息。
4. 接收 PRMS 创建的 Dilution Barcode。
5. 触发标签打印。
6. 向厂务供液系统发送 PGMEA 供液/停止信号。
7. EMO 与供液系统联动。
8. 向报表系统发送汇总报表。
